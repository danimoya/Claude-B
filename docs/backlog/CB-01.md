# CB-01 — Shared state and installed daemon startup

Sprinter: `c701558e08ce`.
GitHub issue: none linked in the retrieved blueprint item.

This scoped change makes the IPC client, CLI launcher and daemon resolve the
same `CB_DATA_DIR`, including relative and `~/` paths. The launcher executes the
daemon installed beside the CLI using the current Node executable, retains the
caller's working directory, and reports process-spawn errors. It no longer
assumes the caller is inside the Claude-B repository.

Regression checks use disposable Unix sockets and mocked launches; no running
daemon, Telegram poller or provider is contacted.

The broader blueprint remains partial. Follow-up work must carry an explicit
caller working directory through session creation, define project/workspace
targeting for existing sessions, and test competing startup attempts and stale
PID/socket ownership. Preserving the startup cwd does not by itself solve
targeting for a daemon that was already running from another directory.
