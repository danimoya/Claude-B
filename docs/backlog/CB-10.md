# CB-10 — unfinished CLI affordances

Sprinter: `8669f2afbdf2`. Associated GitHub issue: none.

Removed `--config`, `--export`, and `--import`, which Commander accepted but
never handled. They now fail as unknown options, and help no longer promises
these operations. Users can edit the selected state's `.env` explicitly and
read persisted session history; a transactional import/export format can be
specified separately rather than shipping no-op commands.

`--logs` now reads the last 100 lines, capped at 64 KiB, from the selected
`CB_DATA_DIR/daemon.log` without connecting to or starting the daemon. Missing
logs are reported clearly. This reads existing log files; some service managers
capture stdout in their own journal instead, and this command does not query
those journals or change logging configuration.

Unit tests cover missing, empty, truncated and multiline log files. Built CLI
artifact checks verify the three removed options are absent/rejected and that
`--logs` reads a disposable state fixture without starting a daemon.

Piped prompts now follow the same parsed submission path as positional prompts.
The CLI preserves literal UTF-8 text, including leading dashes, quotes, newlines
and surrounding whitespace. Input never becomes argv. Model flags work for
normal and fire-and-forget local submission; `--select` selects the session
before a normal submission; `--remote` and `--remote-fire` retain their existing
host targeting behavior. Explicit positional prompts take precedence over stdin.
Administrative commands, help and version bypass the piped prompt reader.
Interactive init retains its own readline flow and bypasses prompt submission.
A selected session with no prompt returns after selection. Cached stdin survives the
existing daemon-start retry without truncation or reparsing.

Tests cover UTF-8 chunk boundaries, whitespace, option-like input, empty streams,
TTY/positional precedence, cached retry and input errors. Built artifact smoke
checks exercise fake Unix IPC for actual CLI model/selection/fire/remote paths
and leave administrative stdin deliberately open to catch accidental waiting.
Failed exact task receipts print the explanation, disconnect and exit with
status 1; unrelated session broadcasts cannot complete the waiting task.

Exact task results are now available with `--task ID`, `--task-key KEY`, and
`--tasks`; `--cancel ID` cancels one queued or running task. `--json` returns
machine-readable receipts. Normal submission waits for that exact task and
prints its exact output; Ctrl+C detaches. `--timeout MS` bounds the wait without
cancelling work. Completed tasks exit 0, accepted/running/uncertain work exits 2,
and terminal failures exit 1. Explicit background submission (`--fire` or
`--remote-fire`) exits 0 once durable acceptance is confirmed, while an uncertain
submission still exits 2. Task lookup never submits a prompt. JSON waits that
reach their deadline return the latest task receipt (or its accepted envelope)
on stdout; selection/progress messages stay on stderr or are omitted.

The CLI chooses a durable task ID and idempotency key before submission. A lost
acknowledgement prints a recovery command rather than replaying the prompt.
Explicit keys can recover the original task across entry points. Remote
submissions preserve receipt IDs; `--remote-task ID` polls status only, while
`--remote-tasks` lists durable receipts. Remote-fire reports acceptance truthfully
without claiming completion. Its optional `--goal` is retained in the durable
remote receipt and resulting notification. IPC polling uses bounded individual
requests within the caller wait budget.

Built artifact checks cover exact output and failure exit codes, local and remote
lost acknowledgements with exactly one mutating request, GET-only resume,
administrative stdin bypass, and generated submission identities. Disposable
built-daemon acceptance additionally exercises literal stdin, cwd/policy,
cancellation, restart recovery and delivery. No production daemon is restarted.
