# CB-06 — container and launcher implementation plan

Sprinter: `83cafcd09892`. Associated GitHub issue: none. Status: partial;
reviewed plan only, no container or production configuration changed.

The imported "fixed" status describes a separate blueprint candidate. On this
branch the Dockerfile still uses floating `node:20-alpine`, runs as root, and
contains no Claude executable. Compose probes `/health` while the server
implements `/api/health`. The entrypoint starts the daemon and waits for a
socket without failing when the readiness loop expires; REST startup follows
regardless. State mounts exist, but caller repositories/workspace ownership are
not defined. These files must not be treated as a verified distribution.

Implement in separate reviewable changes:

1. Select an immutable Node/base image and supported Claude installation method.
   Validate native node-pty compatibility on that exact image. Install the
   runtime as an unprivileged UID with writable explicit state and workspace
   mounts; keep credentials external to images and build arguments.
2. Replace readiness-by-socket-existence with a bounded isolated IPC status
   request, stop startup on failure, and propagate daemon/REST startup failures
   to PID 1. Test signal forwarding and child cleanup under tini. Use the
   package-relative launcher and shared `CB_DATA_DIR` from CB-01.
3. Correct health checks to `/api/health` and define the REST bind/publication
   contract using `CB_REST_HOST`/`CB_REST_PORT`. Specify repository mounts and
   the working directory passed with each submission; a container's `/app`
   must never silently become the user's target repository.
4. Build and run a disposable single-node smoke environment using a fake Claude
   executable and new temporary state. Verify non-root UID, health, one literal
   task, persisted output after recreation, graceful stop, and readiness failure.
   Then test a separate three-node compose project with unique ports/volumes,
   no Telegram poller and no production network or state attachments.
5. Preserve artifact digest, test receipts and state rollback instructions.
   Have the operator validate real workspace access and provider requirements
   before any actual deployment or poller handover (OPERATIONS.md).

The current task forbids production config/service changes and live restarts.
Container execution and publication have not been attempted. The branch's full
source build/tests validate source changes, not these proposed runtime changes.
