# CB-06 — Container distribution and persistent launcher

Sprinter: `83cafcd09892`. Associated GitHub issue: none.

The repository now provides a working non-root container distribution:

- Base image: `node:22.23.4-bookworm-slim` pinned to multi-platform index
  `sha256:5ec23b7c622b00547753bc6ffd78085dd868a68aeb41c8e0a1418f033e13d96d`.
  Node 22 is a [supported LTS release](https://nodejs.org/en/about/previous-releases).
- Claude Code: exact npm version `2.1.319`, installed with npm integrity
  verification and checked by executing `claude --version` during the build.
  [Official setup](https://code.claude.com/docs/en/setup) documents versioned npm
  installation; the [version metadata](https://registry.npmjs.org/@anthropic-ai%2fclaude-code/2.1.319)
  pins the platform packages and package integrity. This version requires Node 22.
- Runtime state is `/home/node/.claude-b`; repository work runs under `/workspace`.
  The [documented config-directory variable](https://code.claude.com/docs/en/env-vars)
  keeps Claude's own files in persistent writable state. No credential enters a
  build argument or image layer.
- The entrypoint verifies the new daemon's exact IPC PID, starts REST over IPC,
  then probes `/api/health`, under a bounded deadline. A dead child, wrong socket,
  invalid configuration, failed REST start or unhealthy response fails startup.
  Tini plus shell traps forward shutdown and reap the daemon.
- The persistent Docker launcher enters the existing container with the caller's
  UID/GID and mapped repository subdirectory. It rejects unrelated workspaces,
  preserves literal arguments, and publishes a localhost REST port only when
  requested. The Docker installer writes this launcher rather than launching
  transient daemons. It requires an explicit verified local or published image;
  no existing registry tag is assumed to include this branch. The source foreground
  launcher resolves its own repository.
- Compose initializes only its project-owned state volumes, then runs all three
  daemons without root as `CB_UID:CB_GID`. The initializer never mounts or changes
  host repository ownership. Published example ports bind to localhost.

Validation on Linux/amd64 used a uniquely named disposable candidate image and
containers, temporary state/repository bind mounts and a fake Claude task
executable. No production volume, network, service, credential or poller was
attached. Checks passed for non-root UID, real installed Claude version, native
node-pty compatibility, IPC/REST readiness, literal task content and repository
cwd, result persistence after container recreation, graceful shutdown, and
startup failure with read-only state. A separate three-node Compose project
verified independent readiness, matching caller UID, writable temporary workspace
and scoped state-volume initialization; all its containers/volumes were removed.
Unit/integration tests separately exercise wrong-daemon identity, readiness
bounds and failures, launcher argument/cwd/mount behavior and installed shim syntax.

These checks validate source and isolated runtime behavior. They do not publish
an image or activate an actual deployment, bot or paid provider. Linux/arm64
uses the pinned multi-platform base and exact native package version but was
not executed on this amd64 host. Operator deployment still follows OPERATIONS.md.

Final durable-task runtime validation additionally installs `procps` and executes
the exact process-ownership field query as the non-root image user during build.
The corrected image passed real isolated task dispatch, workspace/persistence,
read-only startup failure, native PTY and three-host Compose acceptance. See the
[recorded image identity and outcomes](evidence/container-acceptance-2026-11-07.json).
