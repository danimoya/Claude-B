# CB-07 — durable remote task contract

Sprinter: `aca62e809f0f`. GitHub issue: none linked.

Remote submissions persist a local receipt and caller-selected task/idempotency
IDs before any mutating POST. A durable submission claim prevents concurrent
replay. The receiving host returns accepted task receipts; GET polling returns
exact terminal output, failure, cancellation or interruption. Acceptance,
uncertainty and completion are distinct results throughout the client,
orchestrator, REST API, IPC and CLI.

Authentication, refresh, session creation, submission, response bodies, polling
and delays share an absolute caller deadline. Ambiguous response loss retains
the receipt and never triggers a mutating retry or cross-host failover. Only
classified failures proven to precede submission permit retry. Disabled hosts
immediately leave routing. Shutdown closes admission and aborts active network
operations; pending receipts remain recoverable.

`GET /api/orchestration/tasks` and `/:id` expose saved receipts;
`POST /api/orchestration/tasks/:id/resume` resumes remote status reads only.
These authenticated routes return `{tasks}` or `{task}` for saved receipts.
Submission accepts caller `taskId`, `idempotencyKey` (also `Idempotency-Key`),
`waitForCompletion`, and an integer `timeout` from 1 to 300000 milliseconds;
resume accepts the same bounded timeout and completion-wait option. Accepted
or uncertain operations return HTTP 202, while known terminal results return
HTTP 200. Invalid input is 400, absent hosts/receipts are 404, and mismatched
idempotent submissions or a removed receipt host are 409. Transport failures
remain distinct from task results and omit credential-bearing exception text.
`cb --remote-tasks` lists receipts; `cb --remote-task ID` resumes a saved one.
Normal remote submission waits in bounded IPC polling intervals. Background
remote submission returns the actual task and receipt IDs. The daemon recovers
terminal notifications and observes submitted receipts after restart using GET
only; prepared records never become automatic POSTs. Completion enters the same
durable notification outbox as local work.

Tests use controlled authenticated loopback peers, persisted stores and
connection loss/restart fixtures. They cover accepted/completed distinctions,
exact output, cancellation, idempotency, lost acknowledgements, request budgets,
GET-only recovery, disabled hosts and shutdown. No deployed remote host,
provider credential or live task is changed by these checks.
