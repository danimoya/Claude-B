# CB-09 — Hermetic source, artifact and release verification

Sprinter: `6c3c1831e013`. Associated GitHub issue: none.

The source now includes a real built-daemon acceptance harness, package allowlist
checks, native private-server tmux fixtures, multi-platform validation jobs,
release prerequisites and an operational runbook. These are executable checks,
not a proposed rollout or a claim about a separate historical candidate.

`npm run check:artifact` inspects the dry-run npm package, checks built CLI
help/version/logs/stdin behavior, then runs `check-daemon.mjs`. The latter starts
only the built candidate under disposable state, HOME, repositories and fake
Claude. No provider, Telegram or registry credential is inherited. It verifies:

- Exact IPC task submission/results/listing/cancellation, repository cwd and
  default versus explicitly selected bypass policy.
- Authenticated REST HTTP 202 acceptance followed by exact terminal results.
- Literal normal CLI input and successful CLI termination, including results
  that finish before a watcher could subscribe.
- Private local webhook failure, flushed outbox state, graceful daemon restart
  and successful retry with the same event ID and timestamp.
- Abrupt daemon death after a running-output checkpoint, recovery as
  `interrupted`, verified owned orphan termination before readiness, retained
  results and no automatic execution replay.
- Stopped-state backup, deliberate fixture mutation, restore and candidate boot
  with the original exact result, delivery identity and execution count.

Successful acceptance emits a versioned JSON proof with artifact SHA-256 hashes,
Node/platform and explicit outcomes. `CB_ACCEPTANCE_PROOF` saves that receipt
outside disposable fixture state for source/artifact evidence.

Local Linux/amd64 validation on Node.js 20.19.6 passed a fresh isolated build
and the entire built-daemon harness. Native tmux tests also passed in required
mode: literal multiline paste targets only its selected pane, and a recycled
pane's changed process identity is rejected. Every native command uses a unique
`tmux -L` namespace; fixture cleanup never targets the default server. Separate
container acceptance is recorded in CB-06.

CI runs the full normal suite with native mode required on Ubuntu Node.js 20/22
and macOS Node.js 22, followed by build and artifact acceptance. Release jobs
must pass exact-source validation before publication; manual release dispatch
starts in dry-run mode. The configured macOS/Node.js 22 jobs are not presented
as completed local runs: their actual CI results must be retained for release
acceptance. Paid provider and real Telegram entitlement checks are outside these
credential-free tests.

OPERATIONS.md documents private state, receipt lookup, cancellation and recovery,
outbox semantics, source/artifact evidence, immutable publication, operator
identity/workspace/poller checks and rollback. No registry was published, actual
service activated, live daemon restarted or production configuration changed.
