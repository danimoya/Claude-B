# CB-03 — private Telegram authorization

Sprinter: `c58a5e06e1b9`. Associated GitHub issue: none.

New `/start` registrations require an explicit `TELEGRAM_ALLOWED_CHAT_IDS`
entry or a single-use owner-issued challenge, and a private sender matching the chat. Existing owner-paired
private chats remain usable when the allow-list is unset. If an allow-list is
configured, it is enforced again on every command, text prompt, voice message
and callback. Groups and callbacks from a different sender are denied.
Pending voice prompts are owned by their originating chat. Concurrent/repeated
confirmations execute once; confirmations during editing are rejected; failed
submissions preserve the input for an explicit retry. Tests use a fake bot
transport and isolated state, without starting a Telegram poller.

Private enrollment now uses an unpredictable three-minute, single-use `/start`
challenge. Standalone setup fences old updates before publishing the nonce,
requires a fresh private sender matching the chat, and bounds polling and body
reads by one abort deadline. A conflicting poller stops enrollment explicitly.
The running bot exposes owner-triggered `beginPairing(expectedSenderId?)`; only
the digest is persisted, optional sender binding is enforced, and consumption
is persisted together with enrollment before success is acknowledged. Replays,
groups, forged actors, bot senders, wrong/expired nonces and stale updates are
covered by isolated tests. Existing owner-managed allow-list enrollment remains
available and remains an additional restriction on challenge-paired actions.
No actual Telegram request, poller or external message was used for these tests.

Owner IPC and `cb --telegram-pair [sender-id]` create challenges without starting
a second poller. Pending voice recovery is implemented with the CB-08 state
contract. Live Telegram/provider acceptance remains an external test-account
gate; no daemon, production configuration or bot was changed here.
