# CB-04 — truthful prompt completion and persisted results

Sprinter: `3a2ed30579fa`. Associated GitHub issue: none.

The active `claude --print` path now waits for process close and drained output.
Prompt-looking text and separator lines cannot complete a running task.
Nonzero exits, signaled exits and structured provider errors emit `prompt.error`
instead of successful completion. Output and terminal history are written before
hooks and notifications run; write failures are reported as errors. Empty
results overwrite previous output and remove stale structured result files.
Each prompt clears the prior structured result, and stale stream/close events
from a failed child cannot affect a newer prompt. Initial history and spawn
failures also release busy state and emit a terminal error notification.
Daemon IPC, Telegram and fire-and-forget submissions share prompt-ID-correlated
delivery so queued tasks cannot consume each other's notifications. Each sink
is isolated, and WebSocket clients receive success and error terminal events.
Regression tests use fake child processes and isolated files; they never invoke
Claude or desktop services.

Remaining scope: a durable per-prompt journal with task IDs and result lookup;
atomic state/result receipts and process-crash recovery; explicit cancellation
states; persistence of queued and interrupted work; durable notification outbox
with deduplication; and restart reconciliation without replaying prompts.
Direct REST/WS prompt submissions still bypass the daemon delivery helper and
need equivalent hook/inbox/Telegram wiring. Cancellation also needs bounded
timer/listener cleanup and protection against replaying queued work on stop.
Preserve the existing session index until a separately
reviewed migration has rollback and compatibility tests. Provider and daemon
acceptance, including live cancellation, are outside this branch's operational
scope. No daemon is restarted and no production state is migrated here.
