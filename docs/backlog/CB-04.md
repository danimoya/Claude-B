# CB-04 — durable task lifecycle and notification delivery

Sprinter: `3a2ed30579fa`. GitHub issue: none linked.

Every accepted prompt now has an atomic, flushed global task receipt before
execution. Task IDs survive session cleanup and identify the exact prompt,
project, model, permission policy, output, provider result, error and timestamps.
Caller task IDs/idempotency keys deduplicate concurrent and restarted requests;
conflicting submissions fail without execution. Pending/running/completed/error,
cancelled and interrupted states remain distinct. Queued and active cancellation
is bounded, stops owned process groups, and never starts another queued task
while stopping. Restart preserves checkpoints and marks unfinished work
interrupted without replaying it. Native executor PID, UID, process group and
birth identity are flushed before feeding the prompt; restart terminates only
a matching owned executor group before readiness. Unknown or reused identities
are preserved with an explicit recovery explanation and never signalled. Corrupt indices/receipts fail closed and retain
their original bytes. Atomic session/result updates retain legacy state formats.

IPC `task.get`, `task.find`, `task.list`, `task.cancel` and authenticated REST
`GET /api/tasks[/:id]`, `POST /api/tasks`, `POST /api/tasks/:id/cancel` expose the
contract. Submission returns HTTP 202 with `status: accepted`, task ID and current
task status; completion comes from its task receipt. Existing session prompt
and WebSocket submissions use the same store. Original session ownership is
returned on idempotent replay, including after session cleanup.

Terminal task receipts reconstruct notification work after a crash. Versioned,
owner-only outbox records persist per-channel acknowledgments and bounded retry
budgets. Inbox appends/rewrites flush data and directory metadata before ack;
shared-directory locks deduplicate concurrent instances. Network delivery never
locks acceptance. Configured/offline Telegram retries, while intentionally
unconfigured channels are recorded as skipped. Deadlines and shutdown aborts are
bounded; an uncooperative in-flight callback is never overlapped by a retry.
Eight failed attempts per channel dead-letter by default. Permanent rejects and
failed shell commands are retained as failed deliveries instead of replayed.

Hook subscribers have separate flushed receipts: a failed subscriber cannot
rerun successful subscribers. Event ID/time remain stable across delivery and
restart; `EVENT_ID` / `CLAUDE_B_EVENT_ID` are available to shell receivers. Arbitrary
external effects cannot be made exactly-once across a crash between effect and
ack: receivers must deduplicate stable event IDs, and shell commands must handle
that uncertainty. Webhook retry limits are total across durable retries and restarts: configured
zero means one HTTP attempt, one means two, and the default means three.
Webhook 429/5xx/network retries remain bounded; ordinary 4xx
rejects are not resent. Receiver replay windows must match authorized queue age;
stale/permanently rejected deliveries remain inspectable rather than disappearing.

Tests cover persisted acceptance, races, literal/empty/large outputs, queued and
active cancellation, stop/accept races, corrupt-state preservation, restart
interruption, per-channel failure/ack/retry, subscriber deduplication, and every
REST/IPC delivery path. Built-daemon acceptance uses disposable state and a fake
Claude executable. No running daemon or production state was changed.
