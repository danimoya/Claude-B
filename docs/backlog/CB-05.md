# CB-05 — execution policy and shell hook data

Sprinter: `d95b8b55ad60`. No matching GitHub issue was open on 2026-11-07.

The scoped shell fix removes textual payload substitution from operator-authored
commands. `$sessionId`, `$promptId`, `$output`, `$EVENT`, and `$TIMESTAMP` remain
available through environment variables, along with existing `CLAUDE_B_*` names
and `CLAUDE_B_PAYLOAD` JSON. Shell source is never rebuilt from payload values.
Use double quotes when expanding values, for example:

```sh
printf '%s\n' "$sessionId" "$output"
```

Single-quoted `'$output'` now follows ordinary shell rules and prints `$output`
literally. Unquoted variables still undergo normal field splitting and globbing;
quote variables to retain their exact values. Payload aliases must be valid
identifiers beginning with a lowercase letter; uppercase payload keys cannot
replace shell-control variables such as `PATH`, `ENV`, or `BASH_ENV`. Prefixed
payload variables remain available. Event metadata is protected against payload
key collisions. Hooks remain trusted operator-authored shell commands: a command
that explicitly invokes `eval "$output"` asks the shell to evaluate that data.

Regression tests execute actual disposable shell processes with quotes,
semicolons, command substitutions, backticks and newlines in payload values,
verify the literal output, and verify sentinel commands never ran. Alias,
metadata, structured JSON and single-quote compatibility are covered too.

The wider execution-policy blueprint still requires an explicit, persisted
per-session policy, CLI/REST/Telegram selection, migration rules, and truthful
permission-denied results. The canonical source previously always supplied
`--dangerously-skip-permissions`; changing that requires a separate reviewed
compatibility contract across all submission paths. This scoped hook change
alone does not complete CB-05 or authorize changing a running daemon's policy.

The execution policy is now explicit and persisted. Legacy sessions and new
sessions default to `default`, which does not pass a permission-bypass flag.
Only an explicit `bypass` policy adds `--dangerously-skip-permissions`. Select it
with `cb --execution-policy default|bypass`, the authenticated REST session
creation/policy endpoint, or authorized Telegram `/policy <policy> [session-id]`.
Policy changes on busy sessions are rejected. Permission-denied output and input
remain in durable task receipts/history; no automatic policy escalation occurs.
Existing live sessions/configuration were not changed or restarted.
