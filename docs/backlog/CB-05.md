# CB-05 — explicit execution policy and literal shell hook data

Sprinter: `d95b8b55ad60`. Associated GitHub issue: none.

Execution policy is explicit and persisted. Legacy sessions and new sessions
use `default`, which supplies no permission-bypass flag. Only explicit `bypass`
adds `--dangerously-skip-permissions`. CLI submission accepts
`--execution-policy default|bypass`; authenticated REST session/task creation and
the session policy endpoint accept the same enum. Owner IPC `session.policy`
and authorized private Telegram `/policy <default|bypass> [session-id]` update a
managed session, using the selected session when no target is supplied. Native
tmux agents retain the policy of their own invocation.

A session with active, queued or submitting work cannot change policy. Accepted
task receipts retain the policy used for execution. Permission failures remain
visible in task results and history, with the original input retained; no path
automatically escalates to bypass. Tests cover default migration, explicit
selection, pending-work guards and failure receipts. Production sessions and
configuration were not changed or restarted.

Shell hooks receive payload values through environment variables. Operator
command source is never rebuilt from payload text. `$sessionId`, `$promptId`,
`$output`, `$EVENT` and `$TIMESTAMP` remain available, together with the
`CLAUDE_B_*` names and `CLAUDE_B_PAYLOAD` JSON. Stable `EVENT_ID` and
`CLAUDE_B_EVENT_ID` identify delivery retries for receiver deduplication. Quote
values using normal shell rules:

```sh
printf '%s\n' "$sessionId" "$output"
```

Single-quoted `'$output'` prints `$output` literally. Unquoted expansion still
performs shell field splitting and globbing. Payload aliases must be valid
identifiers starting with a lowercase letter; uppercase payload keys cannot
replace control variables such as `PATH`, `ENV` or `BASH_ENV`. Prefixed payload
variables remain available, and payload keys cannot replace event metadata.
Hooks remain trusted operator commands: an explicit `eval "$output"` evaluates
that data because the operator requested it.

Regression tests run disposable shell processes with quotes, semicolons,
command substitutions, backticks and newlines in payload values. They assert
literal output and confirm sentinel commands never execute. Alias, metadata,
JSON and single-quote behavior are covered without touching live services.
